# Рыночные ставки грузоперевозок

Прототип загружает синтетические сделки в PostgreSQL, рассчитывает помесячный коридор ставок по маршрутам и формирует прогноз стоимости рейса. Прогноз и исторические рыночные показатели доступны в отдельных витринах.

## Быстрый запуск

Нужны Docker и Docker Compose. Из корня проекта:

```bash
docker-compose up
```

Для Compose v2 эквивалентная команда — `docker compose up`. PostgreSQL остаётся запущенным, контейнер `pipeline` завершается с кодом 0 после публикации прогноза. При первом запуске в отдельном томе генерируются 300 000 сделок. В логе три JSON-события: `load_window`, `refresh_mart`, `publish_predictions`.

```bash
docker-compose logs pipeline
docker-compose exec postgres psql -U demo -d deals_bigdata
```

Переменные приведены в `.env.example`. Окно ETL по `loading_date` полуоткрытое `[START_DATE, END_DATE)`. Сначала загружается весь источник, затем можно обновлять отдельные окна.

```bash
docker-compose run --rm pipeline python -m etl.run \
  --start-date 2026-09-01 --end-date 2026-10-01 --as-of 2026-10-26
```

Параметр `--skip-ml` обновляет только данные и рыночную витрину. `N_PRICES` применяется при создании пустого тома. Для тестовой БД используется изолированная сеть Compose, порты хоста не публикуются. Внутренняя аутентификация `trust` предназначена для этого локального стенда.

## Слои и обновление

| Слой | Зерно и роль |
|---|---|
| `raw` | Схема и SQL-генератор из комплекта задания. Данные полностью синтетические. |
| `core.deals` | Один идентификатор сделки. Тариф в RUB без НДС, признаки груза, флаги и поля для аналитики. |
| `core.dq_quarantine_prices` | Одна отклонённая сделка, список причин и исходная строка. В логах есть количество строк и срабатываний по правилам. |
| `mart.route_card` | Месяц × отправление × назначение × группа кузова × весовая категория. |
| `mart.ml_price_predictions` | Один прогноз на пару `as_of × price_id`. Метрики прогона и временные границы хранятся в `mart.ml_model_runs`. |

Python управляет этапами и вызывает `psql` через libpq. PostgreSQL 17 выполняет проверки и преобразования наборами строк, поддерживает транзакции и точные перцентили. Для загрузки прогнозов используется `COPY FROM STDIN`. PostgreSQL и Compose покрывают зависимости прототипа без отдельного планировщика. Ту же команду запуска можно вызывать по расписанию с датами нужного окна.

ETL проверяет цены, физические параметры и справочник городов. Валютные строки переводятся по точному `nearest_rate_date` без подстановки курса по дате погрузки. При дублях курса выбирается минимальный `id`. Для RUB курс 1. Недостающая весовая категория рассчитывается после округления до 0,1 т. Валидная внутригородская перевозка сохраняется.

Миграции, перезапись выбранного окна и расчёт рыночной витрины выполняются в одной транзакции. Обновления сериализуются блокировкой PostgreSQL. Повторный запуск не добавляет дублей. Если сделка меняет дату погрузки, при обработке новой даты запись со старой датой удаляется по идентификатору. Для гарантированного обновления обеих партиций повторно обработайте оба окна. Для небольшого прототипа рыночная витрина пересчитывается целиком, чтобы корректно обновить зависимости MoM и YoY. На больших объёмах этот шаг можно ограничить затронутыми ячейками и их календарными зависимостями.

### Рыночный коридор

- Дубли городов разрешаются по минимальному `cities.id` для каждого `gc_id`. Кузова маппятся по `std_id`. Сделка учитывается один раз в каждой подходящей группе. Без связи используется `prices.body_type`, затем «Не указан».
- Даты берутся из `price_dates`. Одна сделка может входить в несколько месяцев, внутри месяца учитывается один раз. Даты позже снимка исключаются до агрегации.
- В расчёт входят прямые факты типов 1, 2, 3, 4, 5, 9 без исходного флага выброса. Уникальные перевозчики считаются по `organization_id` только для типов 3 и 9. Итоги по разным группам кузова нельзя складывать как уникальные сделки.
- MoM и YoY соединяются с точным предыдущим календарным месяцем и месяцем прошлого года. Если ячейка отсутствует, результат `NULL`. Свежесть для HIGH — разница между `as_of` и последней доступной `price_date` внутри ячейки.
- Источник ещё не размечал часть записей, созданных в последний день снимка, 26 октября 2026. Их `outlier_mark = false` по умолчанию, поэтому свежий коридор и метрики тестового периода могут быть чувствительны к выбросам. Флаг используется как есть.

```sql
SELECT month, body_group, weight_category, p25_trip, median_trip, p75_trip,
       p25_km, median_km, p75_km, trips_count, carriers_count,
       reliability_level, mom_pct, yoy_pct
FROM mart.route_card
WHERE loading_city_gcid = 1001 AND unloading_city_gcid = 1003
ORDER BY month DESC, trips_count DESC
LIMIT 20;

SELECT reason, count(*)
FROM core.dq_quarantine_prices
CROSS JOIN LATERAL unnest(reasons) AS r(reason)
GROUP BY reason ORDER BY count(*) DESC;

SELECT as_of, train_start, test_start, model_name, metrics
FROM mart.ml_model_runs ORDER BY as_of DESC;

SELECT price_id, loading_date, actual_price_rub, predicted_price_rub, abs_error_rub, ape_pct
FROM mart.ml_price_predictions
WHERE as_of = DATE '2026-10-26' AND loading_date > as_of
ORDER BY loading_date, price_id
LIMIT 20;
```

### Признаки и оценка модели

CatBoost работает с категориальными признаками без ручного кодирования категорий. На входе только плановые параметры груза и плеча, группа кузова, регионы и координаты обоих городов, год и календарные пары sin/cos. Для ML используется одна основная группа кузова на сделку. Цены, удельные ставки, маржа, флаг выброса и `price_group_stats` отсутствуют в списке признаков. Флаг выброса используется только для отбора исторических фактов.

Обучение идёт на периоде **26.07–04.10.2026**, проверка на **05.10–26.10.2026**, без перемешивания. Параметры модели зафиксированы заранее, `random_seed=42`. Основная оценка считает все допустимые типы фактов. Отдельно показано качество на типах перевозчика 3 и 9. Медиана обучающей выборки служит простым ориентиром. В production для оценки качества во времени понадобятся снимки признаков и явная дата доступности закрывающего факта, которых в входных данных нет.

Будущие заявки отбираются по `loading_date > as_of`, известности заявки на дату снимка и валидным плановым параметрам. Цена и курс для их скоринга не нужны. Факт и обе ошибки остаются `NULL`. Оценка точности возможна после появления факта. Запись прогнозов атомарно заменяет выбранный снимок. Проверка версии защищает от публикации расчёта, если конвейер обновил Core во время обучения.

### Результат воспроизводимого прогона

Проверка проведена на PostgreSQL 17.9, Python 3.12 и зависимостях из `requirements.txt`. Из 300 000 сделок в Core попало 299 797, в карантин — 203 (164 невалидных цен и 39 строк без точного курса). В витрине 203 644 ячейки. Обучение использовало 24 226 строк. Скоринг записал 12 808 тестовых фактов и 5 824 будущие заявки.

| Модель и срез | Строк в test | R² | MAPE, % | RMSE, руб. | MAE, руб. |
|---|---:|---:|---:|---:|---:|
| CatBoost, все допустимые факты | 12 808 | 0,9194 | 15,97 | 54 297 | 28 303 |
| CatBoost, только сделки перевозчика | 4 413 | 0,9210 | 17,80 | 50 360 | 28 289 |
| Медиана train, все допустимые факты | 12 808 | -0,1348 | 90,89 | 203 791 | 122 640 |

MAPE — среднее `abs(прогноз − факт) / факт × 100` по историческим сделкам с положительным фактом. Метрики получены на синтетических данных. Отпечатки Core, карантина, коридора и прогнозов совпали после полного повтора и отдельного backfill за октябрь 2026. SQL и Python проверены сквозным прогоном на локальном PostgreSQL, конфигурация Compose — командой `docker compose config`. Полный старт контейнеров отдельно не проверялся, поскольку на машине нет Docker Engine.

## Проверки

```bash
docker-compose run --rm pipeline python -m unittest discover -s tests -v
docker-compose exec -T postgres psql -X -v ON_ERROR_STOP=1 -U demo -d deals_bigdata < tests/checks.sql
docker-compose run --rm pipeline psql -X -v ON_ERROR_STOP=1 -f tests/edge_cases.sql
docker-compose exec -T postgres psql -XAt -v ON_ERROR_STOP=1 -U demo -d deals_bigdata < tests/fingerprint.sql > before.txt
docker-compose run --rm pipeline
docker-compose exec -T postgres psql -XAt -v ON_ERROR_STOP=1 -U demo -d deals_bigdata < tests/fingerprint.sql > after.txt
diff -u before.txt after.txt
```

Проверки охватывают разбиение по датам, ограниченный набор признаков, полноту разбиения Core/карантин, точные валютные курсы, дедупликацию справочников, коридоры и календарные сравнения, пустой факт у будущих заявок и совпадение содержимого после повторного запуска. Отпечаток исключает служебное время скоринга.

Технические справки: [PostgreSQL 17 · агрегаты](https://www.postgresql.org/docs/17/functions-aggregate.html), [CatBoostRegressor](https://catboost.ai/en/docs/concepts/python-reference_catboostregressor), [Docker Compose · порядок запуска](https://docs.docker.com/compose/how-tos/startup-order/).
